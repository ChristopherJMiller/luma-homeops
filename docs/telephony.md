# Telephony (patchbay)

The house PBX is [patchbay](https://github.com/ChristopherJMiller/patchbay):
Asterisk 22 plus a Go operator. Phones, softphones and people are
Kubernetes resources in git; patchbay compiles the Asterisk and phone
config, serves it to the phones, and walks each device to `Registered`.
Design: `docs/superpowers/specs/2026-10-14-patchbay-design.md`. Deploy plan:
`docs/superpowers/plans/2026-10-15-patchbay-deploy.md`.

| Piece | Where |
|---|---|
| Chart + site values | `cluster/applications/telephony-release.yaml` (Argo `telephony-release`) |
| Phones, softphones, people | `cluster/telephony/` (Argo `telephony`) |
| PBX pod | ns `telephony`, hostNetwork on `top` (192.168.0.240): SIP 5060, RTP 10000-10099, TFTP 69, HTTP 6970 and 8088, control API 9440 |
| Voice VLAN | VLAN 20, 192.168.20.0/24; `VOICE-OUT` lets phones reach only those ports on .240 (`router/ansible/playbooks/firewall.yml`); DHCP option 66 = .240 |
| Secrets | generated by the controller into ns `telephony` (`patchbay-<device>`); nothing in git, no `sign.sh` |
| Firmware | PVC on `rook-ceph-block-ssd`, filled by `patchbay firmware load`; Cisco firmware is never in git (public repo) |

The deviation from the spec: the spec sketches one multi-source app; this
repo uses its usual pair (chart app + resources app).

## The CLI

Build it from the patchbay repo at the deployed tag, then always pass this
cluster's kubeconfig (never rely on `~/.kube/config`):

```sh
cd ~/Repos/patchbay && git checkout v0.1.0-rc.1 && nix develop -c make build   # bin/patchbay
alias pb='~/Repos/patchbay/bin/patchbay --kubeconfig /tmp/galaxy-kubeconfig -n telephony'
pb status                      # every device: state, conditions, the human action; unknown phones
pb softphone qr chris-laptop   # scan in Linphone; the URL works once (--reissue for a new one)
pb phone resync desk           # re-read config now (held while the phone is in a call)
pb firmware load <cisco.zip>   # checks each file's SHA-256 locally, then uploads matches
pb models                      # what each model supports
```

## Common tasks

- **Change a label or number:** edit `cluster/telephony/<device>.yaml`,
  push. The controller recompiles; the agent applies (and rolls back a
  config Asterisk refuses); the phone is told to resync once it is idle.
  Numbers are quoted strings (`number: "100"`).
- **Add a desk phone:** set its switch port to `untagged: 20` in
  `switch/teg-30284.yaml` and `swctl plan` / `swctl apply` (switch/README.md).
  It gets a 192.168.20.x lease and asks .240 for its config; `pb status` lists
  it under unknown phones (also an `UnknownPhone` Event on `patchbay-pbx-config`).
  Add a `Phone` with that MAC to `cluster/telephony/` and the kustomization.
- **Add a softphone:** a `Softphone` in git, then `pb softphone qr <name>`.
- **A phone needs a person:** its `status.humanAction` (shown by `pb status`)
  says exactly what: stage firmware, factory-reset it (hold `#` while
  powering on, then `123456789*0#`), or plug it in.
- **New SIP firmware:** the driver's manifest pins each file's SHA-256, so a
  new Cisco load is a patchbay commit + release, then a chart bump here,
  then `pb firmware load`.

## Upgrades

`telephony-release`'s `targetRevision` is the whole deployment (the chart
pins its image by digest). Renovate automerges patch bumps only; minor and
major wait. Any bump recreates the PBX pod (host ports): calls in progress
drop and phones re-register within their 600 s expiry (TCP phones sooner).

## When something is wrong

- `pb status` first: each condition has a reason and a message.
- Events: `kubectl -n telephony get events --sort-by=.lastTimestamp`.
- Agent view (what the phones fetched, registrations, scrapes):
  `pb status` shows the summary; logs with `kubectl -n telephony logs deploy/patchbay-pbx -c agent`.
- Asterisk: `kubectl -n telephony exec deploy/patchbay-pbx -c asterisk -- asterisk -C /var/lib/patchbay/config/current/asterisk/asterisk.conf -rx 'pjsip show contacts'`.
- Voice VLAN path: `router/scripts/verify-voice-vlan.sh`.

| Down | Calls | Status shows |
|---|---|---|
| controller | keep working | stops updating |
| agent | keep working | `Registered=Unknown` (`AgentUnreachable`) |
| Asterisk / node `top` | none | `Registered=False` (`PBXDown`) |
| bad config | unaffected (rolled back) | `ConfigCurrent=False` (`ApplyFailed`) + Event |

Phones depend on `top`, including during Talos upgrade hops.

## Rollback

Remove `telephony.yaml` and `telephony-release.yaml` from
`cluster/applications/kustomization.yaml` and push: Argo prunes the
workloads. The CRDs and the firmware PVC are kept (`helm.sh/resource-policy:
keep`); delete them by hand only when abandoning patchbay (S4). Phones keep
polling TFTP and come back on their own when the PBX returns.
