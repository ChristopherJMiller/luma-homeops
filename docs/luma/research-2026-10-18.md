# Luma research and review digest (2026-10-18)

These are the verified facts behind the decisions in
`docs/superpowers/specs/2026-10-18-luma-design.md`, condensed from about 17
research and review passes run while brainstorming. Every claim was current
on 2026-10-18. Fast-moving items (SDK issues, release numbers) should be
re-checked before they are relied on. "(est.)" marks an estimate rather
than a measurement.

**Caching:**
- Cache writes cost 1.25× for the 5-minute TTL and 2× for the 1-hour TTL.
  Writing to the cache breaks even after 2 requests (5m) or 3 (1h).
- Prefixes must be at least 512 tokens. A request can have at most 4
  breakpoints. Caches are per model **and per workspace**.

**Other API facts:**
- Batch is 50% off and stacks with caching.
- Web search costs $10 per 1k searches.
- **Preserved thinking:** on the 5.5 models, thinking blocks are bound to
  the exact prefix that produced them. Accounts created on or after
  2026-08-31 get a 400 on edited history. `prefix_mismatch_behavior:
  "drop_block"` exists under the `thinking-binding-controls-2026-08-01`
  beta.
- Mid-conversation `role:"system"` messages work without breaking the cache.
- Anthropic's OpenAI-compatible endpoint **does not cache**.
- The advisor tool went unused without prompting in Anthropic's own
  measurement (0 calls in 198), at +12% cost. Removing it while
  `advisor_tool_result` blocks are in history returns a 400.

**Cost model** (reviewer's estimate for 8 people × 20 turns a day, Haiku as
the default):

| Line item | Monthly |
|---|---|
| Plain Haiku chat | ~$4 |
| Session-start cache writes | ~$2.4 |
| Web search fees | ~$11.5 |
| WebFetch extraction | ~$1.3 |
| HA Assist | ~$2 |
| `deep-think` on Sonnet | $9–15 |
| Chris on the Smart tier | ~$20 |
| Sandbox tasks | ~$25 |
| Computer use | ~$12, on demand |
| Evals (weekly, Haiku-gated) | ~$14 |
| **Total** | **≈ $95–110** |

The tail risks are runaway web search, Opus sandbox tasks, and Haiku prompts
over 100K tokens.

**Local models aren't cheaper.** A ~$2k GPU box costs about $63/month idle,
which buys roughly 30k Haiku agent requests. Justify local on privacy,
offline use and learning.

## Claude Agent SDK (the harness)

### What it gives us

- **Sessions.** It is Claude Code packaged as a library. Sessions have
  ids, resume, `forkSession`, `resumeSessionAt`, and a `SessionStore`
  interface with reference adapters for Postgres, S3 and Redis.
  - Transcripts are keyed by `cwd`, so pin `CLAUDE_CODE_PROJECT_DIR_NAME`.
  - The system prompt is snapshotted on the first request and reused until
    compaction.
- **Remote execution.** `spawnClaudeCodeProcess` (TypeScript) runs the CLI
  remotely, in a VM or container.
- **Hooks.** A `PreToolUse` hook can return `defer`; the turn then ends with
  `tool_deferred`, which gives durable approvals. A SessionStart hook can
  return `additionalContext`.

### Settings that matter

- **Model and permissions:**
  - `permissionMode` must be explicit, because an omitted value can start in
    auto mode.
  - `tools` is the restricting list. `allowedTools` only auto-approves.
  - `settingSources: []` and `strictMcpConfig: true`.
- **Prompt and caching:**
  - **`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` is ignored behind an LLM gateway.**
    Only one system block is sent, so per-person content can't go in the
    system prompt.
  - `CLAUDE_CODE_PROMPT_CACHE_TTL` exists (v2.1.242+). Subagents,
    compaction and titles default to 5m.
  - Tool search is turned off behind a non-first-party `ANTHROPIC_BASE_URL`.
    Set `ENABLE_TOOL_SEARCH=true` if the proxy forwards `tool_reference`.
  - Use CLI ≥ 2.1.268. Older flag-less sessions rebuild the system prompt
    every request.
- **Helper models and web tools:**
  - Set `ANTHROPIC_DEFAULT_HAIKU_MODEL`. Without it, helper calls such as
    WebFetch extraction run on the **main** model when
    `ANTHROPIC_AUTH_TOKEN` is set.
  - WebSearch is a nested request on `web_search_20250305` with
    `max_uses: 8` and caching off. WebFetch is a client-side fetch plus a
    model extraction call, and its domain check calls `api.anthropic.com`.
- **Compaction:** `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (minimum 100000),
  `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`, `precomputeCompactionEnabled`
  (default true).
- **Other env vars:** `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` adds an
  `x-claude-code-request-class` header. `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`.
  `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`.

### Gotchas and terms

- **Issues to design around:**

  | Issue | Problem |
  |---|---|
  | #348 | Stdin closes when the input iterable ends |
  | #391 | A libc probe blocks the event loop for 0.5–5 s on every `query()` |
  | #268 | `listSessions()` spawns a full CLI (~900 MB) |
  | #370 | `defer` can't resume in-process `createSdkMcpServer` tools |
  | #289 | Resume drops tool sequences in large sessions |
  | #432 | `cache_control` in streamed user messages returns 400 |
  | #378 | A stream can outlive its bearer token |
  | #356 | In-process MCP tools are never deferred |

- **Footprint:** a prewarmed spare is about 230–260 MB. Anthropic suggests
  1 GiB and 1 CPU per agent. Pod cold start is 10–30 s.
- **Release churn:** about 25 releases in 30 days.
- **License:** the TypeScript `LICENSE.md` is "All rights reserved" under
  the Commercial Terms. The Python wrapper is MIT, but the CLI it bundles
  is proprietary.
- **Terms:** branding is "Luma, powered by Claude", never "Claude Code".
  Use API keys only. The Commercial Terms say "not for consumer use", which
  Chris reviews before family use.
- **Non-Claude backends are unsupported.** Anthropic says it "doesn't support
  routing Claude Code to non-Claude models through any gateway". Known
  breakages:
  - llama.cpp #25923: a grammar breaks because a tool has
    `maxLength: 524288`;
  - #27107: Qwen templates reject mid-conversation system messages;
  - #27893: temperature is forced to 1;
  - cc#87227: the vLLM prefix-cache hit rate drops from 70% to 8.7%;
  - #92449 and #96154: scaffolding is read as if the user typed it.
- **Prior art:**
  - Anthropic's Kubernetes hosting cookbook puts the API key inside the agent
    pod; Luma doesn't.
  - Managed Agents with self-hosted sandboxes costs $0.08 per session-hour
    and is Claude-only.

## Inference gateway

- **LiteLLM: rejected.** 17 GitHub advisories in 2026, five of them
  critical. Two were exploited in the wild: CVE-2026-42208 (pre-auth SQLi)
  and CVE-2026-42271 (authenticated RCE, in CISA KEV). There was a PyPI
  compromise of 1.82.7 and 1.82.8. It ships a release almost daily, and
  Prisma's memory keeps growing.
- **agentgateway v1.6.0: chosen.** Rust, Linux Foundation.
  - **Passthrough:** the standalone Helm chart runs it with no Gateway API.
    The `detect` route type passes requests through (re-serialised with
    `preserve_order`, so semantically exact) while extracting usage.
  - **Budgets:** per API key, settled after each response, persisted to a
    database.
  - **Pricing gaps:** the catalog has **no `claude-haiku-5-5`**, a single
    cache-write rate, no context tiers and no per-request fees, so its
    dollar figures are informational only.
  - **Metrics:** `agentgateway_gen_ai_client_token_usage{gen_ai_token_type=input|output|input_cache_read|input_cache_write}`.
  - **1.6 behaviour changes:** it prefers Responses, base URLs need `/v1`,
    and paths match exactly.
  - Its five advisories are all in MCP and the controller.
- **Others:**
  - Portkey OSS went stale after Palo Alto Networks bought it.
  - Bifrost has open `cache_control` bugs.
  - Envoy "Agent Router" needs Envoy Gateway.

## MCP

- **The current spec is 2026-07-28.**
  - The protocol is stateless, and **DCR is deprecated in favour of CIMD**.
  - Servers must validate the audience and must not pass tokens through.
  - Multi-round-trip requests (`input_required`) replace server-initiated
    elicitation.
  - Clients send `Mcp-Method`/`Mcp-Name` headers.
  - Enterprise-Managed Authorization (ID-JAG) is a stable extension.
- **Our current gateway, `hyprmcp/mcp-gateway`, is archived.** Its last
  release was 0.4.0 on 2025-12-16; its last push was April 2026.
  - Refresh tokens go directly to Dex.
  - The 401 has no `resource_metadata`.
  - The protected-resource metadata `authorization_servers` and the AS
    metadata `issuer` disagree.
- **ToolHive v0.54** (the alternative). It has an embedded AS with CIMD and
  DCR, RFC 8693 `act` support and Cedar policy. But it is v0.x with
  frequent CIMD bugs (#6186, #6189), runs a proxy pod per server, and needs
  Redis. Obot can't use Dex.
- **Fastmail** has an official remote MCP server at
  `https://api.fastmail.com/mcp` (launched 2026-04-22).
  - Open DCR and public clients (`none`), PKCE S256 only, `offline_access`.
  - JMAP scopes, with read, write and send consent tiers.
  - No CIMD.
- **Home Assistant `mcp_server`:**
  - Since 2026.10 it requires an admin account, except for
    `/api/mcp/assist`.
  - It supports CIMD but not DCR.
  - Entity exposure is global; there are no per-user access lists.
  - HA's `mcp` integration (HA as an MCP client) is OAuth-only.
- **Homelab servers:**
  - `containers/kubernetes-mcp-server` v0.0.67: `read_only`,
    `denied_resources`, `enabled_tools`, `confirmation_rules`.
  - `argoproj-labs/mcp-for-argocd` v0.9.0: `MCP_READ_ONLY`.
  - `grafana/mcp-grafana` v2.0.2: `--disable-write`.
  - No safe Ceph or Talos server exists.

## Identity

**Dex v2.46.0** (2026-10-07) adds:
- per-client `allowedConnectors`, `jti`, ES256 and RP-initiated logout;
- sessions and remembered consent (`DEX_SESSIONS_ENABLED`);
- opt-in `client_credentials`.

**Dex quirks we rely on or avoid:**
- Token exchange only swaps tokens from an upstream identity provider, and
  verifies them with `SkipClientIDCheck: true`. **Never use Dex as an STS.**
- Cross-client `audience` is documented for ID tokens only. Whether access
  tokens carry it is unverified; phase 0a checks.
- Dex access tokens are shaped like ID tokens (`SignAccessToken` →
  `SignIDToken`).

**The Microsoft connector takes email from `userPrincipalName`**, not from
`mail`, and hardcodes `EmailVerified: true`. A UPN must be in one of the
tenant's verified domains, so email is a safe cross-connector key. But
**never** use the generic OIDC connector against Entra `common`: that is
the nOAuth attack.

**Live issues found on 2026-10-18:**
- One-click token theft: open DCR plus `skipApprovalScreen: true`, whose
  `consent.Satisfied()` is true for every client.
- No `expiry` block, so tokens last 24 h.
- gramps-mcp does no auth itself.

**Kubernetes ServiceAccount tokens:** the issuer is
`https://192.168.0.5:6443`, but `jwks_uri` is node-specific and discovery
needs authentication. So workloads are verified with **TokenReview**, which
also returns the pod name and uid.

**Gramps Web:**
- HS256 flask-jwt-extended tokens, 15 minutes.
- `TokenSyncResource` and `issue_access_token(user_id, scope)` (API
  v3.23.0) are the pattern to copy for a token-exchange endpoint.
- Email stopped being unique in #961.
- v26.10.1 carries API 3.23.x. Account linking (#1051/#1053, v3.24.0)
  isn't released yet.

**gramps-mcp:** one shared `AuthManager` holding a password. Per-user mode
needs ASGI middleware, a `ContextVar`, and a token broker.

## Sandboxes, Nix and the network

- **kubernetes-sigs/agent-sandbox** v1.0.7 (2026-10-15), CRDs at `v1beta1`.

    SandboxWarmPool, SandboxClaim (setting `env` forces a cold start).

- **Nix:** build with nix2container (`initializeNixDatabase`,

  - nix-snapshotter needs Nix on the host.
  - nixkube's CSI driver is privileged.
- **Attic:** signs on the server and supports wildcard-token scopes. A push
  token therefore amounts to a cache vouching for whatever it uploads.
  `allowed-hosts` currently lists only the public name. Its PVC is 50 Gi on

- **B2 lifecycle:** rules apply per prefix and run daily (minimum 1 day).
  S3-API lifecycle needs versioning, and Object Lock blocks lifecycle
  deletes.
- **kube-network-policies:**
  - **v1.1.2** includes the fix for hostNetwork pods being enrolled
    (#380/#389).
  - Talos 1.13 bundles v1.1.0; Talos 1.14 bundles v1.1.2.
  - The Talos 1.10 kernel has `NFT_QUEUE` built in.
  - Use `--v=1` (siderolabs/talos#13391).
  - It fails open at boot.
- **Dormant NetworkPolicies:** argo-cd has six. MetalLB's two **select
  nothing** (`instance=metallb-release` vs `metallb`).
- **smokescreen** (stripe), measured:
  - 1k deny entries cost 1.3 ms per connection, 10k cost 13 ms, 100k cost
    140 ms.
  - There is no hot reload.
  - `*.x` does not match bare `x`.
  - A raw IPv4 CONNECT in an `open` role skips the domain lists, which needs
    a patch.
  - **Blocky** v0.35.0 works as its resolver. Use
    `loading.strategy: blocking`.
- **Filter lists:**
  - **Allowlist:** GitHub `gh-aw` `ecosystem_domains.json` (MIT, about 324
    hosts) is the best package allowlist.
  - **Reference only:** LOTS (lots-project.com) is too broad to block
    wholesale.
  - **HaGeZi** (GPL-3.0): Pro has 202k entries; TIF mini, medium and full

  - **Phishing Army extended** has 157k entries. **URLhaus** needs an

  - **Not in any list:** webhook.site, pipedream, pastebin, trycloudflare,

- **Computer use:**
  - Claude uses `computer_toolset_20260801` at 1280×720 to 1366×768. A
    1280×720 screenshot is about 1.2k tokens.
  - Prefer Playwright MCP over CDP (accessibility snapshots).
  - Neko (WebRTC) can't be reverse-proxied.
  - Open models: UI-Mate-9B scores 66.2 on OSWorld-Verified.

## Artifacts (empirical three-engine test)

The test ran in Chromium 1217, Firefox 1511 and WebKit 2272. With
`CSP: sandbox allow-scripts` and no `allow-same-origin`:

- **Blocked:**
  - The document has an opaque origin (`self.origin` is `"null"`).
  - `document.cookie`, localStorage, sessionStorage and IndexedDB all
    throw.
  - Service workers are unavailable.
  - `window.open` and form posts are blocked.
  - Scripted `fetch` and `<img>` requests carry **no** cookies, including to
    the artifact host itself.
- **Still allowed:**
  - The page can navigate itself, and that top-level GET carries Lax
    cookies.
  - The document request itself carries every `.chrismiller.xyz` cookie.
- **Breaks:** CORP `same-origin`/`same-site` blocks the artifact's own
  assets.

Sandpack iframes use `allow-same-origin`, so a self-hosted bundler needs a
separate registrable domain. LibreChat's shares are conversation snapshots,
with public/private as a single global switch.

## Cluster facts discovered (2026-10-18)

- **Memory:**
  - Requests are 81.9 of 90.3 GiB (89–91% per node).
  - About 9.8 GiB of real use is **BestEffort**: nfs-ganesha (4.7 GiB),
    both MDS, HA, Grafana, trivy and MetalLB.
  - Rook holds 53.3 GiB of requests. Mons request 4 Gi each and use about
    0.5 Gi.
  - A single drain leaves about 21.7 GiB Pending.
- **Ceph:**
  - The SSD pool has 142 GiB MAX AVAIL, shared with CephFS metadata.
  - Mons, OSDs and MDS run on the pod network.
  - kube-proxy runs in nftables mode.
- **Prometheus** loads rules only from namespace `prometheus` with
  `prometheus=kube-prometheus, role=alert-rules`. Only 3 rule groups load,
  and **no stock alerts are active**.
- **fluent-bit** ships every container's logs to **Azure Log Analytics** and
  to router syslog. `K8S-Logging.Exclude` is Off, and there is no Loki.
- **The `middle` memtest trigger** (ceph-doctor, read-only):
  - Bad non-primary replicas: 1.16 (10-11, osd.6), 1.b (10-14, osd.4,
    repaired 10-15), 1.c (10-16, osd.6, a persistent `_verify_csum`

  - osd.4 also had an in-flight crc retry (10-12).
  - SMART is clean, and there are no EDAC metrics.

## Research method

Each pass ran as a background agent against primary sources: docs, source
code, release notes and GitHub issues. Some passes ran their own benchmarks:
smokescreen ACL scaling, the three-engine browser test, and string checks
on the CLI binary.

The four adversarial reviews of the v1 design were:
- **security:** it refuted the nOAuth critical, and found the
  approver-identity, memory-poisoning, Gramps SSRF and artifact identity
  issues;
- **ops/capacity:** BestEffort OOM risk, the HDD throttle gap, the rule
  selector, Azure logs, SPOFs;
- **cost/caching:** the dynamic boundary behind gateways, tool-set changes,
  helper models, search fees, evals;
- **scope:** lean phase 1, phase reorder, mobile basics, the BFF.

A builder check and a consistency pass followed. Their findings are folded
into spec v2.
