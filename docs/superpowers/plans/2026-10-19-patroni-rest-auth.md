# Patroni REST API auth for every `acid-*` cluster Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Patroni member of the seven `acid-*` clusters rejects unauthenticated writes on :8008, while the postgres-operator, Patroni peers (failsafe) and `patronictl` keep working.

**Architecture:**
- **Credentials:** Patroni's own `PATRONI_RESTAPI_USERNAME` / `PATRONI_RESTAPI_PASSWORD`. Each cluster gets them from its own sealed Secret `patroni-restapi`, through the CR's `spec.env`.
- **Spilo patch:** Spilo's runit script deletes all but nine environment variables before it starts Patroni, so the two variables never arrive. Our Spilo images add those two names to the script's allowlist.
- **Operator patch:** the operator's Patroni client sends no credentials, in v1.11.0 and in upstream master alike. Our operator image adds Basic auth to its write calls, read from the same Secret in the cluster's namespace.
- **Rollout:** images → Secrets → operator → canary → the remaining clusters, one at a time.

**Tech Stack:**
- postgres-operator v1.11.0 (ckotzbauer chart 1.12.2)
- Spilo `spilo-16:3.2-p3` (Patroni 3.2.2, PG 16), plus our `spilo-vchord`
- Go 1.21.7
- GitHub Actions → GHCR
- Sealed Secrets, Argo CD

**Spec:** `docs/luma.md`, "Final review round (2026-10-19)": "**Patroni REST API (8008):** verify whether it has auth. If it's open, **fix it now** for every `acid-*` cluster, as its own small plan." ## Design decisions

- **D1: Basic auth, not `allowlist`.** An allowlist filters by source IP. The operator's pod IP changes on every restart, and in-cluster traffic isn't SNATed, so there's no stable address to allow. `allowlist_include_members` would block the operator.
- **D2: One Secret per cluster namespace, all named `patroni-restapi`** (keys `username`, `password`), following the `logical-backup-s3` precedent.
  - With a shared credential, anyone who can read one app namespace's Secrets, or exec into one Spilo pod, could drive every cluster.
  - Per-namespace credentials keep today's boundary, which is the superuser Secret.
- **D3: Env, not the config file.**
  - Exec'd `patronictl` and `inplace_upgrade.py` inherit the container env, so they authenticate with no extra work.
  - **Consequence:** `/run/postgres.yml` will *still* show no `authentication` after the fix. Checks must read the daemon's env (Task 1).
- **D4: Patch the operator; don't proxy it.**
  - The alternative was `HTTP_PROXY` plus a header-injecting proxy sidecar. The chart can't add env or sidecars, and a static header means one shared credential (against D2).
  - The patch is about 60 lines plus tests, and it can go upstream.
- **D5: No TLS.**
  - The operator hardcodes `http://`, so Basic credentials cross the flannel VXLAN in clear.
  - Reading that traffic needs node or L2 access, which already gives far more.
- **D6: Not NetworkPolicy.** flannel enforces none. Enforcement is Luma phase 4 (spec D25). When it lands, a :8008 policy is extra defence, not a replacement.
- **D7: Our own Spilo for all seven clusters.**
  - This ends "every other cluster stays on stock Spilo" (`images/spilo-vchord` header).
  - The patch is one regex in a shell script, with build-time assertions. Each cluster pins its own digest and rolls on its own.
  - Still, a bad build can now reach six clusters, not one (open question 1).

## Global Constraints

- CLAUDE.md S1–S9 apply to every task.
- **S2 (GitOps):** every cluster change is a commit synced by Argo. Direct `kubectl` is limited to:
  - reads: `get`, plus `exec` for `patronictl list`, `GET` on :8008 and `/proc` reads;
  - `kubectl delete pod`, during rollback only;
  - the Task 1 `--probe` writes, after Chris's OK.
- **The only write verb this plan sends to :8008 by hand is `DELETE /restart`.** It goes only to a member whose `GET /patroni` shows no `scheduled_restart`, which makes it a no-op. Never hand-send `POST`, `PATCH` or `PUT` to :8008.
- **Never print a password (S9):**
  - Generate passwords straight into the `.secret.yaml`.
  - Show Secrets as keys only (`jq '.data | keys'`).
  - Authenticated curls run *inside* the Spilo container as `sh -c '… -u "$PATRONI_RESTAPI_USERNAME:$PATRONI_RESTAPI_PASSWORD" …'`. The single quotes stop the local shell expanding them.
  - Use `git diff --no-textconv` for anything that leaves the terminal.
- **Credential format:** username `patroni`. Password `openssl rand -hex 32`, hex only so it needs no quoting, distinct per cluster. Secret `patroni-restapi`, keys `username` and `password`; the operator patch hardcodes that name.
- **Upstream pins:**
  - operator source `v1.11.0` = commit `0f96eb20bfcc7381dacf0ec673e7d0824f442570`, built with Go 1.21.7 (upstream's version);
  - operator runtime base `registry.opensource.zalan.do/acid/postgres-operator:v1.11.0@sha256:20ba5dbb3f2d3566eddb4cd0616379cc73e55bacce398301e577d4f6353ad4e9`;
  - Spilo base `ghcr.io/zalando/spilo-16:3.2-p3@sha256:b59493aaba6e35c017f22954fa09548060616c8669c58ab2b368689f0ee21884`.
- **Our images:** `ghcr.io/christopherjmiller/{postgres-operator,spilo,spilo-vchord}`, always pinned as `:sha-<short>@sha256:<digest>`. Operator version string: `v1.11.0-galaxy.1`.
- **Order is load-bearing:** images → all 7 Secrets present → operator → canary → the rest. Rollback runs in exact reverse. **Never revert the operator while any cluster still has auth on.**
- **One cluster in flight at a time.** Don't roll while any of these holds:
  - a node is cordoned or draining, or Talos/etcd work is under way (S5);
  - Ceph is outside its usual state;
  - the K8s API is flapping, because the mixed-auth window relies on failsafe not being needed;
  - it is 00:30–02:00 UTC, the logical-backup window (`30 00 * * *`).
- **Watch each roll** with the `safe-rollout` skill or Monitor, never a sleep loop.
- **`acid-attic` and `acid-ha` are single-member.** A roll is a full restart outage, so each needs Chris's go at the time.

## Review Focus

1. **The operator's switchover against a leader that requires auth.** The first roll of a cluster can't prove it, because that switchover goes to the old, auth-free leader. Task 6 Step 5 forces a second roll on the canary, and Step 6 checks the Switchover event.
2. **A CR that references `patroni-restapi` before the Secret exists.** The pod fails with `CreateContainerConfigError`; on attic or ha that is an outage. Task 4 gates on all 7 Secrets. Task 1's script reports `BROKEN` for env refs to a missing Secret.
3. **A Spilo base bump that changes the runit filter.** The `sed` then silently does nothing, and auth is off while everything looks green. Task 3's Dockerfile `grep -qF` assertions fail the build, and `test-restapi-env.sh` runs the real filter plus Patroni's `Config`.
4. **A new `postgresql` CR created without the env or image** (`acid-luma` in Luma phase 1) leaves that cluster open. Task 1's script audits every CR it finds, not a fixed list. Task 9 adds the step to the Luma plan and to the runbook.
5. **Password rotation.** The operator reads the Secret on each request, but pods keep the old value until they restart. Operator writes then get 401, and the roll's own switchover fails. Task 2's `TestAuthClientDoReadsSecretPerRequest` pins the operator side. Task 9's runbook gives the manual sequence.

## Rollback

- **One cluster (Tasks 6–8):** `git revert` that cluster's commit(s). The operator rolls the pods back to stock Spilo without the env; the patched operator authenticates the switchover to the auth-on leader.
  - **If that switchover fails** (the operator patch is broken): in the leader pod, `patronictl switchover --candidate <replica> --force`; its env holds the credentials. It may print `503, status unknown` but complete, so re-check `patronictl list` after about 15 s. Then `kubectl delete pod` the old leader, to clear the known in-container `invalid permissions` restart.
- **Operator (Task 5):** revert *only* when the audit shows no member with `daemon=ok`. With upstream's operator back in place, any auth-on cluster's next roll stalls at the switchover, and its CR Patroni/parameter changes stop applying.
- **Secrets (Task 4):** harmless to leave; remove them last. **Images (Tasks 2–3):** nothing to undo while they're unreferenced.
- **Triggers:**
  - `CreateContainerConfigError` or `CrashLoopBackOff` on a Spilo pod;
  - an event `Switchover … FAILED`;
  - app DB errors that persist more than 5 minutes after a roll;
  - an operator `level=error` naming `patroni-restapi`.
